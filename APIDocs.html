/api/events
Create a new event
ORGANIZERADMIN
▼
Request Body Fields
FieldTypeRequiredDescription
titlestringRequiredNon-blank title of the event
descriptionstringOptionalLong-form description (stored as TEXT)
dateLocalDateTimeRequiredISO 8601 datetime — must be in the future, e.g. "2025-10-01T09:00:00"
locationstringRequiredNon-blank venue/address string
maxAttendanceintRequiredMinimum value: 1
eventStatusenumRequiredOne of: SCHEDULED, COMPLETED, CANCELED

Example Request
// POST /api/events
{
  "title": "Tech Summit 2025",
  "description": "Annual technology summit for developers",
  "date": "2025-09-15T10:00:00",
  "location": "Cairo Hub, Maadi",
  "maxAttendance": 200,
  "eventStatus": "SCHEDULED",
  "paymentRequired": true,
  "price": 150.00,
  "organizerId": 2,
  "categoryId": 3
}
Side Effects
On success, a notification is automatically broadcast to all users with ROLE_ATTENDEE, and an email is sent to each of them with the event details.
Response Codes
201 Created (returns event ID) 400 Validation error 403 Insufficient role

Partially update an event (all fields optional)
ORGANIZERADMIN
▼
Notes
Only send the fields you wish to update — all fields in DetailedEventDto default to null and are only applied when present. The date must still be in the future if provided.

{

All users registered for this event receive an in-app notification and email about the update.

200 OK (true) 400 Invalid data / past date 404 Event not found

Payments (PayMob)
/api/payments
POST
/api/payments/pay?amountCents={n}&userId={n}&eventId={n}
Initiate a PayMob card payment — returns iFrame URL
AUTHENTICATEDATTENDEEORGANIZERADMIN
▼
Query Parameters
ParameterTypeRequiredDescription
amountCentsintRequiredPayment amount in EGP cents (e.g. 15000 = 150 EGP). Note: the service multiplies this by 100 internally — pass the base price in EGP × 100.
userIdintRequiredID of the paying user
eventIdintRequiredID of the event being paid for
Example Request
// POST /api/payments/pay?amountCents=150&userId=5&eventId=1
// No body needed — all params are query strings
Success Response (200)
"https://accept.paymob.com/api/acceptance/iframes/897502?payment_token=..."
Payment Flow
This endpoint executes a 3-step PayMob flow: 1. Authenticate → get token  2. Create order  3. Generate payment key → build iFrame URL.

Redirect the user to the returned URL. PayMob will call back your /api/payments/callback with the result.
Response Codes
200 OK (iFrame URL string) 500 PayMob integration error
POST
/api/payments/callback?hmac={signature}
PayMob webhook — do not call this manually
PUBLIC
▼
Notes
This endpoint is called by PayMob's servers, not by your frontend. It must remain public (no JWT required).

On a successful HMAC-verified payment, two things happen automatically: 1) A payment record is saved to the database. 2) The user is registered to the event via RegistrationService.registerUserToEvent().

The endpoint always returns 200 OK regardless of HMAC result to prevent PayMob retry loops.
Response Codes
200 OK (always)
